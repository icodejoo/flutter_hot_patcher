# P2 探路：字节级函数等价判定是否可行 —— linker 的地基

**问题**：SPEC §4.2 把"逐字节等价判定"列为 linker 的核心步骤，但没展开一个隐藏的
硬问题：两份快照里**逻辑没变**的函数，会不会因为地址重定位（pc-relative 的 call
目标、对象池 slot 偏移随快照布局变化）被误判成不等价？如果会，naive memcmp 不成立，
必须做符号化比对。反过来，字节相等是否就一定能判"等价"？

跑：`DART_SDK_SRC=/root/dart/sdk ./run_all.sh`

## 三个实验结果（2026-07-30，x86-64，ReleaseX64）

### A. 位置无关性：`reloc_base` vs `reloc_shifted`（前面加了无关函数，整体布局被扰动）
三个函数在两份快照里**地址都平移了 0x70**，但机器码字节**完全相同**
（`naive_bytes_equal=True`），包括调库 + 引用字符串常量的 `callsLib`。

原因（看 `caller` 反汇编）：
- 函数间调用是 **pc-relative `call rel32`**（`e8 2f 00 00 00`，rel32=目标−下一条PC）。
  caller 和 pureLeaf 一起平移、相对距离不变 → rel32 不变 → 字节不变。
- 对象池 / 常量访问是 **`mov 0x80(%r14)`** 这种通过 r14（池/线程寄存器）+ 固定偏移，
  不含绝对地址 → 平移不影响。

→ **Dart AOT 函数码有很强的位置无关性**，布局平移本身不改字节。这降低了 linker 难度。

### B. 编译确定性：同一份源码编译两次
函数机器码字节 **run-to-run 完全一致**（地址也一致）。但**整个快照文件 md5 不同**
（build-id / 时间戳之类元数据）。

→ **确定性成立，但必须做函数级比对，不能 md5 整个文件**。这是 diff 方案的绝对前提。

### C. 字节等价不充分（关键陷阱）：`reloc_base` vs `reloc_patchleaf`
`pureLeaf` 函数体改一个常量（`x*3+1`→`x*3+2`，同宽立即数、机器码大小不变）：
```
pureLeaf: naive_bytes_equal=False   (add $0x1 → add $0x2，正确判为不等价)
caller  : naive_bytes_equal=True    (字节完全相同！地址、rel32 都没变)
```
但 `caller` 直调的 `pureLeaf` 被替换了。若 linker 只看字节把 caller 判"等价、指回
基线机器码"，caller 的 `call pureLeaf` 会跳到**基线旧 pureLeaf（x*3+1）**，行为错误。

→ **字节相等 ≠ 可指回基线**。SPEC §4.2 那句"逐字节等价**且其内部直调/内联目标仍
有效**"里，后半句才是传递闭包的真正来源。

## 核心结论：linker 等价判定 = 两条件不动点

一个函数 F 可判"等价（入口指回基线机器码、走全速原生）"，当且仅当：
1. **F 自身机器码逐字节等价**（位置无关性 + 确定性使这可行、可复现），**且**
2. **F 直调 / 内联的所有目标也都判为等价**（否则 F 会调到被替换的旧逻辑）。

任一不满足 → F 转解释。条件 2 让判定成为**依赖传播 / 不动点计算**：
被改函数 → 直调它的也失效 → 向上蔓延 → 止于虚调用点（dispatch table 可重定向，
Gate 1 V2 已验证）。这就是"受影响传递闭包"，靠**调用目标失效**传播，不只靠字节变化。

这个模型统一了 Gate 2 的用例：
- **V6 去虚化路由** = 被去虚化的静态直调，走条件 2 传播。
- **V7 内联级联** = F 内联进调用者，调用者字节直接含 F 旧逻辑 → 条件 1 直接触发。
- **V8 真实改函数体** = 条件 1（自身变）+ 条件 2（调用者传播）。
- **V9 类字段布局变更** = 访问者字节因偏移变而不等价（条件 1，见 `../probe_field_layout/`）
  → 访问者的调用者走条件 2 传播。
- **V10** = 测这个闭包的规模 / 解释比例。

## 对最小 diff linker 的要求（下一步实现）

1. 按符号名（≈ `CanonicalName`）对齐新旧快照的同名函数。
2. 逐字节比对得到"自身不等价"的初始集合（条件 1）。
3. 反汇编每个函数、解析 `call rel32` 目标符号，建**调用图**。
4. 从初始集合沿调用图反向传播（谁直调了不等价函数 → 也不等价），算不动点（条件 2）。
5. 输出最终"必须转解释"集合 = 传递闭包；无变化者指回基线。规模数据即 V10 输入。

**保守边界**：任何无法可靠解析的调用（间接 / 尾调用 / 未识别目标）一律按"目标可能
失效"处理 → 判不等价、转解释（宁慢不崩，符合 SPEC §4.2 保守优先）。
