## 使用选项实际生效的输入

`compile_all` 和四个 `load_*` 选项使用各 fixture 的 JIT kernel。先从该 kernel 生成双方各自的 core 快照，再生成 app-jit；`compile_all` 实际扩大指令产物，再加载其非空数据和指令文件验证 `load_isolate_snapshot_instructions`。省略必需输入和错误路径的结果也逐次保存。

`vm_snapshot_data` 和 `vm_snapshot_instructions` 的 core 输入也是对应 fixture 的 JIT kernel。core 模式的 VM 指令文件按工具契约为空占位；去掉输出选项后文件不再生成，加载不存在的指令文件则失败，因此没有把空占位文件当作未知实现。

链接参数使用该 fixture 的真实参考 CT、DT、FT 和对象池表。CT/OP 成对输入，分别省略一端的对照均拒绝。此次 base 和 patch 使用同一份表，验证有效的恒等重链接；原矩阵还保留 `base_patch` 和 `base_insert` 的非恒等场景。FT 参数改变快照，DT 恒等表保持产物相同；缺失文件对照确认 DT/FT 的路径确实被读取。

`dd_slot_mapping` 使用该 fixture 的真实 FunctionKey 构造 voters，实际生成非空 resolution；省略映射时该输出缺失或为空。`help`、`version`、`sdk_version` 属于进程元数据选项，命令包含对应 fixture 输入，但工具按契约提前退出，不将其宣称为读取了快照。

既有 `hello` 和 `base_dd` 的源码与 AOT kernel 字节相同，本次沿用三个标准 fixture 的名称并分别执行，公开这一重合关系。
